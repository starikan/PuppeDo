# Worktree в agent harness

## Где что лежит

| Путь | Что это |
|------|---------|
| **Корень проекта** (`/app/project` или ваш mount) | Основная рабочая копия git |
| `.agents-sessions/` | **Worktree-источник** сессий агентов (отдельная orphan-ветка, не symlink) |
| `.tasks/` | **Worktree-источник** Obsidian-хранилища задач (отдельная orphan-ветка, не symlink) |
| `.agents-data/` | Обычная папка с данными агентов в корне |
| `.git-project-manifest.json` | Манифест git-workspace проекта (shared/protected пути, orphan-ветки, роли) |
| `.worktrees/<имя>/` | Git worktree для отдельной задачи/ветки |

В **task-worktree** (`.worktrees/<имя>/`) папки из манифеста с `symlinkInTaskWorktree` не равным `false` — это **symlink** на каталоги в корне основного репозитория. Их создаёт `create-worktree.sh`, не вручную.

## Пункты меню контейнера

### Инициализировать новый проект

Полная настройка git-репозитория для работы с агентами:
- Создаёт git-репозиторий и первый коммит (необходим для веток и task-worktree)
- Добавляет манифест `.git-project-manifest.json` с описанием shared-папок
- Настраивает `.gitignore` для служебных каталогов (`.agents-sessions`, `.tasks`, `.agents-data`, `.worktrees`)
- Создаёт каталог `.agents-data`
- Создаёт shared worktree-источники `.agents-sessions` и `.tasks` как отдельные orphan-ветки

**Сценарии:** первичная настройка нового или существующего репозитория.

---

### Инициализировать shared worktree

Создаёт или восстанавливает worktree-источники `.agents-sessions` (сессии агентов) и `.tasks` (Obsidian-хранилище задач).
Каждый — отдельная orphan-ветка, блокируется от случайного удаления.

**Сценарии:** после клонирования репозитория (shared worktree не клонируются), если shared-папки были повреждены или удалены.

---

### Создать / перейти в task-worktree

Создаёт git-worktree для отдельной ветки/задачи в `.worktrees/<имя>/`:
- Ветка создаётся от текущей или указывается явно
- Подключаются symlink на shared-папки из манифеста
- Активный каталог меню переключается на этот worktree

Внутри worktree агент видит только код своей ветки и shared-папки (через symlink).

**Сценарии:** начало работы над новой задачей, переключение между задачами.

---

### Запустить агента в task-worktree

То же создание или открытие существующего worktree, но активный каталог меню **не меняется**.
Агент запускается однократно в этом worktree и завершается.

**Сценарии:** параллельная работа над несколькими задачами, быстрая проверка или запуск без смены контекста.

---

### Очистить битые worktree

Проверяет зарегистрированные git-worktree, показывает устаревшие (папка удалена, ветка не существует).
После подтверждения выполняет `git worktree prune`.

**Сценарии:** ошибка «missing but already registered worktree»; после ручного удаления папки worktree.

---

### Сбросить глобальный worktree

Возвращает активный каталог меню в корень основного репозитория.

**Сценарии:** после работы в task-worktree нужно вернуться к общей кодовой базе для worktree-независимых операций.

---

Вне контейнера (`run.cmd`) task-worktree не используются — работа идёт в основной папке проекта.

## Типичный сценарий

```
# один раз на новый проект: Инициализировать новый проект
# создать worktree для задачи, например feature-x
# агент видит код ветки и shared-папки через symlink
```

Параллельно несколько task-worktree — каждый со своей веткой.

Если Git пишет «missing but already registered worktree», используйте пункт *Очистить битые worktree*.
Он чистит только устаревшую регистрацию, не удаляя ветку и существующие папки.

Все операции доступны через **меню контейнера**. Подробное описание каждого пункта — в разделе «Пункты меню контейнера» выше.

## Требования

- Git 2.42+ (относительные пути worktree)
- Перед созданием task-worktree в репозитории должен быть хотя бы один коммит (пункт *Инициализировать новый проект* создаёт его автоматически)
- Не запускайте скрипты создания worktree из дополнительного worktree (где `.git` — файл)

## `.git-project-manifest.json`

Единый манифест git-workspace проекта в корне репозитория.
Формат: JSON (`version`, `entries[]`). Каждая запись описывает shared-путь или protected worktree.

При создании `.worktrees/<имя>/` скрипт создания worktree читает манифест и подключает
symlink для записей с `symlinkInTaskWorktree` не равным `false`; если поле не задано, оно считается `true`.

Подробнее о формате: `git-project-manifest.defaults.json`.
Шаблон `.walk-ignore`.

Стандартный набор после инициализации:

- `.agents-sessions` — worktree-источник сессий (protected-worktree, роль `sessions-output`)
- `.tasks` — worktree-источник задач (protected-worktree, роль `tasks-vault`, postInit)
- `.agents-data` — shared-folder (только symlink)
- `.data` — shared-folder (только symlink)
- `.worktrees` — shared-folder (каталог task-worktree, gitignore)
